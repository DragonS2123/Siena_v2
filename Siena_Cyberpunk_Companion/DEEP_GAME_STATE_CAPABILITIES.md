# Deep Game State capability audit

Audit target: Cyberpunk 2077 `3.0.80.51928`, CET `1.37.1`, RED4ext, redscript, Codeware, RedHttpClient and RedFileSystem installed. Audit date: 2026-07-15, re-verified and extended 2026-07-16. This document is evidence for a later v0.8 design; it is not a production telemetry contract.

## Evidence levels and local sources

- **yes**: getter is already running in Siena or exists in an installed working Lua mod, OR was directly observed succeeding/failing in a real CET log from this machine.
- **candidate**: type/method/field name is confirmed present in compiled game bytecode, TweakDB, an installed REDscript mod, or official CET documentation, but its exact Lua return shape/owning-class/accessibility still needs an in-game probe on this game build.
- **partial**: a safe subset is confirmed; requested detail is not.
- **no direct**: no reliable bounded read-only getter was found. No method is invented.
- **confirmed broken**: the exact call was directly observed throwing at runtime on this installed build (a real log excerpt exists), so it must not be marked "yes" even though older documentation/community knowledge claims it works.

Local evidence inspected:

- `bridge/cet/siena_cyberpunk_observer/state_reader.lua` and the hash-identical installed v0.7 copy (re-verified 2026-07-16 via direct MD5 comparison against the live installed copy at `B:\SteamLibrary\...\cyber_engine_tweaks\mods\siena_cyberpunk_observer` — all 12 files match byte-for-byte).
- Installed CET mods: AppearanceMenuMod, VisualHolster, InteractiveAccessories, GameEntityExaminerTool, WeatherSwitcher and the GameUI libraries bundled by installed mods.
- Installed REDscript: EquipmentEx, Virtual Atelier (`virtual-atelier-full`), VirtualCarDealer, BrowserExtension and Enhanced Vehicle System.
- `r6/cache/final.redscripts`, `final.redscripts.modded`, `tweakdb.bin`, and `tweakdb_ep1.bin`.
- **New 2026-07-16**: direct ASCII-string extraction from the compiled `r6/cache/final.redscripts` bytecode cache (16 MB, ~106k unique printable strings ≥4 chars) and `r6/cache/tweakdb.bin` (42 MB, ~93k unique strings ≥6 chars) via a one-off Python regex scan (`re.findall(rb'[\x20-\x7e]{4,}', data)`), read-only, no game files modified, no decompiler used. Redscript's compiler embeds identifier/enum-member/field name strings in its bytecode cache for reflection and TweakDB binding, so real method/stat/field names can be recovered this way even without NativeDB or WolvenKit — but string presence alone does NOT prove which class owns a symbol, its exact signature, or that CET's Lua binding exposes it under the same name. Every finding from this method is marked **candidate**, never **yes**, until a live Lua call confirms it.
- Direct runtime evidence from the installed **GameEntityExaminerTool**'s own log files (`GameEntityExaminerTool.1.log`/`.2.log`/`.3.log`/`.log`, most recent entries 2026-07-15 23:15:51 UTC+03:00): its main-loop call `Game.GetTargetingSystem():GetComponentClosestToCrosshair(Game.GetPlayer(), nil)` is observed **throwing** `"Function 'GetComponentClosestToCrosshair' parameter 3 must be gameTargetSearchQuery."` on every call on this exact installed build — see the corrected "Enemies | crosshair target" row below. This is the single most important correction in this revision: a method previously marked "yes/high-medium" is confirmed broken by a real log, not by inference.
- `scripting.log` confirms `siena_cyberpunk_observer` (production) is alive and sending accepted telemetry every ~5s as of 2026-07-15 23:19:45 — used only to confirm the production mod is unaffected by this audit, never edited or queried further.
- CET scripting documentation for [handles and `Game.GetPlayer`](https://wiki.redmodding.org/cyber-engine-tweaks/scripting-api), [TweakDB getters](https://wiki.redmodding.org/cyber-engine-tweaks/cet-functions/tweakdb), and [CET/Codeware resource limitations](https://wiki.redmodding.org/cyber-engine-tweaks/cet-and-codeware).

NativeDB and WolvenKit metadata were not installed locally. Compiled redscripts confirm symbol presence but do not prove a stable CET Lua signature or return shape.

## APIs absent or not production-safe

- No confirmed direct CET getter for installed cyberdeck, its slot count (candidate: `CyberdeckProgram1..8`, untested), equipped quickhacks, resolved RAM cost (candidate static base: `MinigameActionType_Record.MemoryCost`), upload time, duration, cooldown, spread, queued hacks, active trace, or hacks available on a target.
- Current and maximum RAM are live-confirmed through `gamedataStatPoolType.Memory`; RAM regeneration remains unconfirmed and excluded.
- No confirmed bounded nearby-entity enumeration or enemy-netrunner classifier. Aggregate detection percentage and wanted-level now have named-field/event candidates (see above) but no confirmed owning-class getter.
- No confirmed stable current quest/objective, general dialogue-menu state, save-transition, perk graph, skill progression, or free point getters. Phone-call state specifically now has a `gamedataStatPoolType.PhoneCallDuration` candidate.
- **`GetComponentClosestToCrosshair(player, nil)` is confirmed BROKEN on this exact installed build (CET 1.37.1 / game 3.0.80.51928) — do not treat as working even though it appears in multiple installed mods' source and was previously marked "yes" in this document.**
- Full inventory/world/TweakDB enumeration is too costly for a gameplay polling loop even where technically possible.
- `Dump`, `DumpType`, and `GameDump` are diagnostic expansion tools, not production data contracts; they can create huge logs and unstable shapes.

## Unsafe methods and boundaries

The audit found many mutating examples in installed mods and official cheat documentation. Siena research must never call item give/remove, equip/unequip, attribute/point modification, quest fact/entry mutation, status-effect apply/remove, vehicle enable/mount, teleport, spawn/despawn, kill, or TweakDB set/create/clone/delete/update methods. `pcall` recovers Lua/native binding errors but cannot make an inherently mutating or crash-prone native call safe.

Resource references (`rRef`/`raRef`) are not safely accessible through plain CET; Codeware is required for those reference-backed resources. Codeware is not otherwise required by the current harness. REDscript is the preferred future boundary for typed events, equipment/development enumeration, journal tracking, quickhack action context, and state-machine/blackboard observation. TweakDB is suitable for static metadata after a runtime item/action ID is known, not as the source of current player state.

## Runtime-only research gaps

The manual harness exists to determine actual return types for the candidate calls. Player-dependent APIs require a loaded save; vehicle data requires a mounted vehicle; target data requires a current crosshair target (**note: the crosshair call itself is confirmed broken on this build — see above**). As of 2026-07-16 the harness now DOES attempt a small, deliberately bounded set of textually-well-evidenced candidates that were previously skipped entirely: `gamedataStatPoolType.Memory` (current + max, in `probe_stat_pools`), a "Memory" stat name (in `probe_stats`), the 8 `AttachmentSlots.CyberdeckProgram1..8` slot paths (in `probe_quickhacks`, reusing the already-confirmed `GetItemInSlot` method), and the bare existence of `Game.GetPreventionSystem()` (in `probe_target`). None of these is assumed to work — each is `pcall`-wrapped exactly like every other probe and will simply log `error` if the name/enum member doesn't exist, exactly as designed. The harness still does NOT attempt nearby-entity enumeration, quest/objective discovery, stealth/detection/wanted getters (no confirmed owning class for any of those yet), or anything requiring a constructed `gameTargetSearchQuery` (no local evidence of how to build one).
