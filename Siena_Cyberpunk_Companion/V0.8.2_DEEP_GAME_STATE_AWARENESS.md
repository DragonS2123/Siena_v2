# v0.8.2 — Deep Game State Awareness

v0.8.2 is a backend/frontend interpretation layer over the live-tested v0.8.1 nullable `deep_game_state` contract. It adds no Cyberpunk runtime call, game write, HTTP client, endpoint, transport or WebSocket. The installed CET observer remains bridge version `0.8.1` because its reader contract did not change.

## Event synthesis

`DeepGameStateAwareness` owns session-scoped health, RAM and weapon latches. A source/session change removes the previous session's latch state. Invalid, unavailable or pre-game samples do not advance the state machines.

Emitted wire events:

- health: `player_health_low`, `player_health_critical`, `player_health_recovered`;
- RAM: `player_ram_low`, `player_ram_exhausted`, `player_ram_recovered`;
- weapon: `weapon_drawn`, `weapon_holstered`, `weapon_changed`;
- bounded status count: `status_effects_increased`, `status_effects_decreased`.

Existing `vehicle_entered`/`vehicle_exited` handling is reused unchanged. No additional vehicle event family was added.

When a valid deep health contract is present, legacy health threshold emitters are bypassed to prevent duplicate low/critical events. Payloads without `deep_game_state` retain the v0.7 path.

## Thresholds and hysteresis

Health:

- low at `<= 25%`;
- critical at `<= 12%`;
- recovered at `>= 40%`, only after low or critical.

RAM:

- low at `<= 25%`;
- exhausted at `<= 10%`;
- recovered at `>= 60%`, only after low or exhausted.

Percentages are calculated only from finite current/maximum values with `current >= 0` and `maximum > 0`. Remaining within a latched state emits nothing; critical/exhausted may follow low; recovery rearms the normal state.

## Weapon and status rules

Weapon identity is normalized from the existing stable `record_id`. The `Items.*` value embedded in a CET `ToTweakDBID` debug representation is extracted; `userdata:` values are rejected. Draw/holster transitions depend only on the explicit `drawn` boolean, so a `WeaponRight` fallback never creates repeated `weapon_drawn`. `weapon_changed` requires two non-null, unequal stable identities while draw state itself remains unchanged.

Status awareness compares only `observed_count` from consecutive packets in the same session. It does not name, classify or infer causes for effects.

## SceneContext

Current telemetry refreshes SceneContext even when no event crosses a threshold. Added nullable fields:

- `health_current`, `health_maximum`, `health_percent`, `health_state`;
- `ram_current`, `ram_maximum`, `ram_percent`, `ram_state`;
- `active_weapon_record_id`, `weapon_drawn`, `status_effect_count`;
- `level`, `street_cred`, `armor`;
- availability guards `player_available`, `session_available`, `is_pre_game`.

The legacy `health_max` field remains populated for compatibility. Scene updates use the existing event bus and `/ws` connection.

## Reaction and voice policy

- health critical is P0 and retains the existing critical cooldown/budget bypass;
- health low and RAM exhausted are high-priority meaningful warnings;
- RAM low and recovery are medium priority;
- weapon and status events are low priority;
- weapon reactions are normally suppressed and become eligible only in an active combat scene;
- low RAM and weapon reactions use text-only focuses under the existing voice policy; only high RAM exhaustion is voice-eligible;
- unavailable/loading/pre-game scenes are suppressed before reaction reservation;
- the existing scene budget, minimum interval, semantic duplicate guard, event cooldown and voice repetition guard remain active.

Prompts receive only bounded scalar state. They do not receive handles, object pointers, enemies, quickhacks, causes or invented combat details.

## Frontend

The existing panel has one compact `Deep Game State` card showing health, RAM, shortened stable weapon identity plus drawn/holstered state, status count, level/street cred and armor. Null and invalid resource values render as `—`. It consumes the existing state envelope on the existing WebSocket.

## Explicit exclusions

v0.8.2 does not implement targets, nearby entities, quickhacks, cyberware, perks, quests, full inventory, status-effect identifiers, new CET APIs, game writes or another transport.
