# v0.8.1 — first safe Deep Game State slice

v0.8.1 extends the protocol additively with optional `deep_game_state`. Existing v0.7 payloads remain valid when the property is absent. The existing `POST /api/v1/telemetry/state`, sequence/session dedupe, RedHttpClient transport and single `/ws` endpoint are unchanged.

## Payload

`deep_game_state` contains five nullable domain objects plus nullable domain capability flags:

- `player`: entity/session availability, pre-game state, world position and mounted-vehicle presence;
- `stats`: level, street cred, armor, power level, health stat and memory stat;
- `stat_pools`: current/maximum health and current/maximum memory (RAM);
- `weapon`: whether the active weapon is drawn, its TweakDB record ID from `GetItemID().id`, and `active`/`weapon_right`/`none` source;
- `status_effects`: bounded observed count, truncation flag and configured limit. v0.8.1 does not claim effect identity or buff/debuff classification because no identity getter was live-confirmed.

Bridge hello adds `deep_player`, `deep_stats`, `deep_stat_pools`, `deep_weapon`, and `deep_status_effects`. They default to `false`, so older hello payloads remain accepted.

## Polling and safety

- Existing telemetry and health/RAM sampling: 250 ms.
- Active/holstered weapon sampling: 500 ms.
- Bounded status-effect sampling: 1000 ms, at most 32 entries inspected; entry 33 is checked only to set `truncated`.
- Static stats sampling: 5000 ms.
- Every CET method call is protected by `pcall`; player/session caches are cleared when no player is available.
- The implementation is read-only. It adds no game writes, endpoint, WebSocket or HTTP client.

## Explicitly deferred

Targets, nearby entities, cyberware, quickhacks, quests, perks, full inventory, ammo, weapon mods/damage, effect identities, RAM regeneration and every gameplay write remain deferred until separately live-confirmed.
