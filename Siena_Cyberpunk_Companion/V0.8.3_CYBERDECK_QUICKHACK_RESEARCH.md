## Static metadata boundary

Safe static reads after a stable installed item ID is discovered are display/localization key, item type, equipment area, record quality, item/record tags and iconic classification. `DisplayName()` returns a localization key-like value; it is not necessarily localized display text.

`MemoryCost`, upload time, duration, cooldown and spread-related symbols exist in action/record schemas. They must not be queried by appending guessed flats to the program item ID. A confirmed program-item-to-action-record relationship is required first. Even then, `MemoryCost` would be a static base value, not the actual target/perk/deck-modified runtime cost.

## Safety restrictions

The research mod remains disabled by default and has no update/draw loop, HTTP, backend connection, transport, writes, spawning, give/remove, equip/unequip, TweakDB mutation, unrestricted inventory enumeration, target scan, nearby entity scan or automatic collection. It never logs an unbounded table.

## Production recommendation

No v0.8.4 production implementation should be made from source evidence alone. If the live matrix confirms both deck discovery and deck-part results, the narrow safe slice is:

- nullable equipped cyberdeck stable TweakDB ID;
- nullable deck item type/equipment-area classification;
- nullable static quality/tier and a small allowlisted tag set;
- nullable bounded installed-program stable IDs with explicit slot IDs;
- nullable empty/used/program-capacity counts only when the three slot getters agree.

Keep base RAM cost, upload time, duration, cooldown, spread, trace, queued hacks and target-available quickhacks blocked until their item-to-action and resolved-runtime paths are independently confirmed.
