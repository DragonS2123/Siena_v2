# v0.9.0 — Siena NPC Runtime Research

Status: v0.9.0.1 source correction, 2026-07-17. The first v0.9.0 Gate-0 test was performed by the user; this correction pass did not launch the game. Nothing below claims that Siena spawned, moved, looked at the player, or cleaned up successfully at runtime.

## First live Gate-0 result and v0.9.0.1 correction

The first manual runtime test confirmed that the research mod loaded without automatic action and that `Game.GetDynamicEntitySystem()`, `IsReady()`, `IsRestored()`, `DynamicEntitySpec.new()`, and CName/tag construction were available. No entity was spawned.

It also proved the original session guard wrong: `npc_research.lua:24` called `player:IsPreGame()`, but that method is nil on the returned runtime player object. The guard then treated a valid loaded player as unavailable, so the transform probes never ran. The reported `vector_path=false` and `quaternion_path=false` therefore did not prove those transform APIs broken; they were downstream of the session rejection. `entity_id_helper_visible=false` likewise exposed an unnecessary diagnostic assumption rather than a lifecycle blocker.

v0.9.0.1 makes these narrow changes:

- Player/session availability follows the already live-used production path: protected `Game.GetPlayer()` with non-nil player as the primary loaded-session signal.
- Optional pre-game state follows `state_reader.lua:407–418` and research `probes.lua:116–122`: `Game.GetSystemRequestsHandler():IsPreGame()`. Confirmed `true` blocks the session; `false` permits it; unavailable remains nullable and does not invalidate a real player.
- Spawn additionally requires both DynamicEntitySystem `IsReady()==true` and `IsRestored()==true`.
- Nearby position uses the installed AMM `Modules/util.lua:475–478` pattern: real player world position plus bounded forward offset through `Vector4.new`, with 2.0 m distance and 0.10 m vertical offset.
- Orientation now reuses the player's returned `Quaternion` directly through `player:GetWorldOrientation()`, as locally demonstrated throughout AMM, including `Modules/util.lua:520`. No Quaternion constructor or Euler-to-quaternion conversion is used.
- `CreateEntity`'s returned `EntityID` is stored and passed directly to `IsManaged`, `IsSpawning`, `IsSpawned`, `GetEntity`, and `DeleteEntity`, exactly matching installed Codeware declarations at lines 43425–43433. No global EntityID helper is required.
- Codeware listener registration remains deferred and is explicitly not a Gate-1 blocker. No redscript bridge was added.

Follow, Come Here, and Look At remain blocked until the tagged entity resolves as `NPCPuppet`. Stay and Clear Look At remain safe no-ops when it does not. Spawn is still manual, disabled by default, unique-tag guarded, non-persistent, and blocked whenever player, system readiness/restoration, nearby position, or orientation is unavailable.

## Scope and result

A separate CET Lua harness now expresses the smallest source-confirmed lifecycle, movement, and gaze experiments. It defaults off, performs no action except through a hotkey, creates at most one tagged temporary entity, has no polling or transport, and does not touch the production observer, backend, frontend, reaction system, TTS, or Build Awareness. No redscript bridge was added: the installed Codeware declarations and installed AMM Lua examples show that the required Gate 0–4 calls are visible from CET. A redscript service remains necessary if a future build requires `DynamicEntitySystem.RegisterListener`, because CET has no source-confirmed `ref<IScriptable>` listener target in this harness.

## Gate design and confirmed calls

### Gate 0 — capability only

`Probe Runtime` checks player presence, `IsPreGame`, system presence, `IsReady`, `IsRestored`, `DynamicEntitySpec.new`, vector/quaternion and `CName` construction. It never calls `CreateEntity`. Listener declarations are logged as source-confirmed and CET listener-target construction as unavailable.

### Gate 1 — one spawn/despawn

Spawn requires `enabled=true`, a player, `IsPreGame()==false`, a ready entity system, and no managed `GetTaggedID("SienaNpcResearch")`. It sets only `recordID`, never `templatePath`; position is 2.0 m along the player's forward vector plus 0.10 m vertical offset; orientation uses the AMM-confirmed conversion. Defaults are `persistState=false`, `persistSpawn=false`, `alwaysSpawned=false`, `active=true`, tag set, and `spawnInView=true`. The latter matches installed AMM source but remains a live-test item rather than a proven safest value.

Only the returned `EntityID` is stored. Despawn cancels the one stored movement command, clears look-at if resolved, deletes that ID through the dynamic system, and clears references. A missing entity is accepted. The unique tag guards duplicate creation and allows manual cleanup after a lost local reference.

### Gate 2 — bounded validation

`Status` reads one tagged ID only: managed/spawning/spawned, resolved entity, bounded runtime-class probes, appearance, position, alive state, AI controller, and ReactionManager. It performs no component dump and no world/nearby scan. A source-confirmed read-only attitude-toward-player getter and reliable NPC combat-state getter were not found, so they are logged unavailable. Consequently the operator must immediately press Despawn on observed hostility; automatic hostility response is not claimed and this candidate cannot graduate until that gap is resolved.

### Gate 3 — movement

`Follow` submits one AMM-confirmed native `AIFollowTargetCommand` targeting only the current player, desired distance 2.5 m, walking, and `teleport=false`. `Stay` cancels the stored command. `Come Here` submits one navigation-enabled `AIMoveToCommand` toward a safe point 2 m in front of the player with `ignoreNavigation=false`. Each replacement cancels the prior command. No attack, weapon, role, vehicle, attitude, or rescue-teleport command exists.

Vehicle entry tolerance remains a manual runtime test. No per-frame reissue exists.

### Gate 4 — gaze; animation blocked

`Look At Player` uses the resolved entity's `ReactionManager:ActivateReactionLookAt(player, false, 1, true, true)`; `Clear Look At` calls `DeactiveLookAt`. Neither touches the player camera/head tracking. Idle animation and Stop Animation hotkeys are absent because installed evidence requires a larger workspot/spawner path whose bounded ownership and cleanup were not proven.

### Gate 5 — session cleanup

The spec is non-persistent and never auto-restored. `PlayerPuppet.OnDetach` and CET `onShutdown` request cancellation/deletion when the local research ID exists. A new session always requires Spawn. Despawn also tolerates a missing ID and can resolve the unique tag. No polling loop was added merely to watch lifecycle state.

This design still requires live proof for main-menu transition, save reload, another-save load, Reload All Mods, normal exit, unexpected player loss, and loss of the entity system. If the system becomes unavailable during cleanup, the harness clears local state and reports failure; non-persistence is expected to prevent save carry-over, but this must not be promoted as runtime-confirmed.

## Manual installation and test procedure

The coding task did not install anything. With the game closed:

```powershell
.\scripts\install_siena_npc_research.ps1 -GamePath 'B:\SteamLibrary\steamapps\common\Cyberpunk 2077'
.\scripts\verify_siena_npc_research.ps1 -GamePath 'B:\SteamLibrary\steamapps\common\Cyberpunk 2077'
```

Installation preserves an existing research copy under `<game root>\siena_npc_research_backups` and copies only `.lua`, `.json`, and `.md` research files. Edit only the installed research `config.lua` to `enabled=true`, then start the game manually.

Run in order and stop at the first failure:

1. In active gameplay press Probe Runtime. Require player/session/system/spec/construction checks and `IsReady=true`.
2. Press Spawn once, wait, then Status. Require one tag, managed/spawned/resolved, `NPCPuppet`, alive, and an AI controller. Press Spawn again and require `duplicate_blocked`.
3. Visually verify non-hostility. If hostile/combat starts, press Despawn immediately, mark candidate unsafe, and do not retry.
4. Press Follow, walk, enter/exit a vehicle, then Stay. Verify no weapon/combat/teleport behavior.
5. Press Come Here once. Verify native navigation and safe stopping distance.
6. Press Look At Player and Clear Look At. Verify reversible NPC-only gaze.
7. Execute lifecycle cases A–J from the task: normal/double despawn, main menu, reload same/other save, Reload All Mods, normal exit/re-entry, double spawn, and unload while following. After every case require no duplicate, stale command, persisted NPC, crash, or quest/world mutation.
8. Retain `siena_npc_research.log`, CET `scripting.log`, RED4ext log, and redscript current log for evidence.

Every log line includes UTC timestamp, a player-EntityID-derived session marker (or `none`/`unavailable`), level, gate, command, and a compact result. The session marker is diagnostic, not a durable cross-save identity.

Uninstall with the game closed:

```powershell
.\scripts\uninstall_siena_npc_research.ps1 -GamePath 'B:\SteamLibrary\steamapps\common\Cyberpunk 2077' -Confirm:$false
```

The uninstaller validates the exact target and research manifest and removes only `mods\siena_npc_research`. External backups remain for manual review.
